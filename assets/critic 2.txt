Yes. I checked the actual Scene 08 code, and I think I see the real problem you’re describing.

It is not simply “the wheel animation is too fast.” There are two architectural problems.

First, Antigravity creates the wheel rotations separately:

wheels.forEach(w => {
  gsap.to(w, {
    rotation: 360,
    duration: 0.45,
    repeat: -1,
    ease: 'none'
  });
});

Those infinite GSAP animations are not attached to this.tl.

But when the scene exits, the cleanup only does:

this.tl.kill();

So the wheel animations are left running.

That means every time Scene 08 is entered again, it can create another set of infinite wheel tweens without properly cleaning up the previous ones.

Second, it's animating the SVG <g> elements using CSS/GSAP rotation with things like:

<g id="s8-bus-wheel-front" style="transform-origin:130px 64px;">

That is a fragile way to handle SVG wheel transforms, especially when combined with repeated scene entry and other transforms. The rotation origin should be explicitly controlled in SVG coordinates, and the wheel animation should be isolated from the vehicle's other transforms.

So the actual problem is more like:

SVG transform handling + infinite tween leakage + scene re-entry = wheel transformation going completely nuts.

And I would not tell Antigravity merely “fix the wheel size.”

I'd tell it to replace the wheel implementation cleanly:

Make each wheel a self-contained SVG group.
Give each wheel a fixed SVG coordinate center.
Rotate around that exact center.
Use a single managed GSAP timeline/context for all wheel animations.
Kill/revert those animations in exit().
Never apply scale to the wheel groups.
Never let vehicle-stage transforms affect the wheel's internal geometry.
Ensure the wheel's rendered diameter remains constant throughout the entire scene.
Test Scene 08, exit it, re-enter it, and replay it multiple times.

So yes, your observation that the wheels are expanding uncontrollably is legitimate. It's not just an aesthetic issue. The current animation architecture is sloppy there.

And honestly, I'd go one step further: the vehicle itself should use one parent motion transform, while wheel rotation happens inside the vehicle, independently. That gives us:

vehicle
 ├── body
 ├── window
 ├── lights
 ├── wheel
 │    └── rotate only
 └── wheel
      └── rotate only

while:

vehicle → moves through world
wheels  → rotate in place

That's the correct mental model for the scene.
