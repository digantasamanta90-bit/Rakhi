1. Project Overview
WORKING TITLE: For Anwesha, From Your Brother
PROJECT TYPE: Personalized interactive digital Rakhi experience
PRIMARY OBJECTIVE: Turn a physical KitKat gift into a memorable digital + physical moment through a QR-triggered seven-scene website.
PRIMARY INTERACTION MODEL: Tap-driven full-screen scene progression with optional discoverable interactions inside scenes.
BACKEND REQUIREMENT: None. No backend, database, authentication, or server-side state is required for the planned experience.
NARRATIVE PRINCIPLE: The website is a small interactive experience, not a generic Rakhi greeting page.
CENTRAL IDEA
The website is not the gift by itself. The website and the physical KitKat are designed to behave as one combined surprise. The QR code is the bridge between the physical object and the digital story.
Source-derived framing: The planning document explicitly evolved from a very small greeting page into a heavier animated experience once the creator decided to use strong animation, music, an eye-catching theme, and additional personalization. The architecture was then formalized as seven scenes with a scene-by-scene implementation plan.

2.1 Narrative identity
Build the site as a lovingly overengineered personal gift made by one brother for one sister.
Alternate beautiful visual storytelling with sibling humor so the emotional tone never becomes one-note.
Use personalization strategically rather than filling every scene with photographs.
Preserve negative space and pauses. The experience should know when to be still.
Every major visual element should have narrative purpose: thread = sibling bond, portraits = personalization, KitKat = physical anchor, code motifs = why a website exists, recap = cumulative journey.
2.2 Project constraints and assumptions
The experience is intended to be buildable by one person with AI coding assistance and limited time.
The website should work without a backend.
Audio begins only after explicit user interaction to respect browser autoplay behavior.
Optional features must never block progression.
Exact font names, exact color HEX values, final portrait assets, final music file, and the final personal message are not yet fully locked in the source and must be treated as TBD rather than invented.

PRIMARY FLOW RULE
The main journey is linear. Optional interactions can enrich a scene but must never be required to unlock the next core scene.
6. Global UX Rules
Use seven full-screen scenes rather than a conventional long-scroll page.
No visible navigation menu is required. The story itself is the navigation.
Primary progression is user-controlled. Do not auto-advance the user through scenes.
Buttons appear only after the scene has had enough time to establish its moment.
Optional interactions remain secondary and cannot block the primary CTA.
Persistent audio controls become available once music begins.
No page reloads between scenes.
All scenes must preserve mobile usability and avoid horizontal overflow.
Visual transitions should transform or dissolve the current world rather than abruptly replacing it.
